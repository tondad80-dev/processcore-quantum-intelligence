A Windows path bug found during AI-assisted code review

A configuration scanner could count the same Windows file twice. The interesting part is how the finding, correction, regression test and upstream acceptance can each be inspected.

Antonín Dospiva · Published 15 November 2026 · Case evidence: 12 November 2026

The outcome: a merged contribution to trustgate, with a correction made after AI review. The initial Factory output did not catch this Windows edge case.

One file, two path strings

The change added Cursor and VS Code Insiders user-profile configuration to trustgate’s home scan. On Windows, the scanner could discover a profile through its static AppData/Roaming/… list and again through the APPDATA environment variable.

If those spellings differed only in letter case, a string-membership check treated them as different paths. On a case-insensitive Windows filesystem they could identify the same file. The scanner could therefore count that file twice and retain duplicate findings.

CodeRabbit identified this issue in its review of PR #19 (opens in a new window). This was a path-deduplication defect; the case does not establish a newly discovered security exploit.

A minimal comparison example

These illustrative paths show the comparison problem without reading a filesystem:

from pathlib import PureWindowsPath

a = "AppData/Roaming/Cursor/User/settings.json"
b = "appdata/roaming/Cursor/User/settings.json"

assert a != b
assert PureWindowsPath(a) == PureWindowsPath(b)

PureWindowsPath supplies Windows path-comparison semantics even when the example runs on another operating system. This example is a reproduction of the equality distinction, not a rerun of the upstream scanner or a test of every Windows filesystem configuration.

The correction and its regression test

With ChatGPT Codex assistance, I changed the deduplication key to PureWindowsPath and kept the first path spelling in the output. The fixing commit (opens in a new window) also updates the native-Windows integration case and adds test_windows_appdata_case_variants_are_not_duplicates.

The new regression case supplies mixed-case aPpDaTa/rOaMiNg and checks that the six settings/tasks paths for Code, Code - Insiders and Cursor occur exactly once, using the expected original spellings. Its file-existence behavior is mocked; that test must be distinguished from the native Windows integration case.

All nine jobs in the recorded final-head GitHub CI run (opens in a new window) passed, including Linux, Windows and macOS tests. The maintainer merged the PR on 12 November 2026. These are the recorded results of that submission; this article did not rerun CI.

What a technical lead can take from it

For a cross-platform scanner, a useful acceptance condition is concrete: two spellings of the same logical input must not create two findings. That condition belongs in regression coverage alongside the normal configuration cases.

The practical result here is narrower than a claim that AI-generated code is generally reliable. One contribution passed review, correction and CI and was accepted upstream. The failure found after generation is part of the evidence.
