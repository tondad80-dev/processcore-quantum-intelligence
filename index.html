Public architecture

Authority is established before interpretation.

ProcessCore separates the path that establishes evidence identity and authority from downstream human or AI interpretation.

01

Evidence

Observable system or project state is captured as explicit, bounded evidence.

02

Provenance

Source identity, scope, lineage and currentness are attached to the evidence path.

03

Authority

Explicit rules determine what may be treated as authoritative for the current project and version.

04

Interpretation

Humans and AI may interpret the result without redefining the evidence underneath it.

Control-path invariant: ACTUAL_STATE ≠ EXPECTED_STATE ≠ POLICY_DECISION ≠ AUTHORIZATION ≠ EFFECT. Detecting a difference does not create permission to change it.

AI Factory

From one controlled run to repeatable software work.

The target is a reusable software factory with human authority and inspectable evidence. AgriCore provides the first independent workload. Later validation and adoption work must have its own reconciled evidence chain; a new AgriCore version alone does not prove factory reuse.

Identity and authority: the specification, model response and materialized artifact retain separate identities. Generation, validation, adoption and deployment remain separately accountable steps.
Post-v0.4 control boundary

Detection, policy and authorization are separate.

Current research keeps actual state, expected state, policy decision, authorization and effect as distinct boundaries. A system may detect drift and even produce a policy decision without thereby gaining authority to change reality.

Persistence boundary: one successful bounded invocation is still not continuing execution authority. PERSISTENCE ≠ ACTIVATION ≠ EXECUTION AUTHORITY ≠ EFFECT.

Actual vs expected

Observed state is evidence. Expected state comes from valid project-scoped authority. Their difference is a classification result, not remediation authority.

Policy decision

A deterministic policy decision may establish whether an effect is eligible for consideration. It does not itself authorize the effect.

Authorization + effect

Any state-changing effect requires separate explicit authorization. If an effect occurs, its receipt and post-effect observation must remain independently inspectable and create new evidence.

Version boundary: this post-v0.4 work remains bounded research and validation. The bounded no-effect invocation is not proof of general runtime readiness, not a declared ProcessCore v0.5 release, not live autonomous remediation and not a production-readiness claim.
AgriCore · independent working demonstrator

A practical supplier-search workflow.

AgriCore is being developed to compare agricultural supplier candidates against a commodity, price target and search area. Source material and optional cost assumptions help the user inspect a candidate before treating it as a usable offer.

Define the search

Select a commodity, price target and area. Transport, packaging and loss assumptions can refine the comparison.

Inspect the source

Review archived candidates alongside their original material. A search match does not by itself confirm price, stock or delivery.

Decide what to verify

Identify missing terms and prepare supplier questions. Confirmation remains a separate step before a purchasing decision.

Latest owner-reported snapshot — 10 October 2026: version 0.1.32; 20 candidates in archives; supplier emails prepared, none sent in the reported step. Live search and supplier delivery were not verified by this review.

Validation semantics

Validation is not authority.

ProcessCore has repeatedly preserved validator failures for read-only reconciliation rather than treating a red result as automatic proof that the underlying implementation or authoritative state is wrong.

Documented reconciliations have shown cases where the authoritative contract remained coherent while a validator expected a different representation. The validation logic itself therefore becomes part of the audit surface.

evidence ≠ validation

Evidence exists independently of the rule set used to test it.

validation ≠ authority

A red validator result does not automatically redefine the authoritative project state.

authority ≠ interpretation

Authority is established before downstream human or AI interpretation.

Claim boundary: “Validation is not authority” is presented here as a ProcessCore architectural conclusion from documented project cases, not as a quotation from an external standard.
Scope and next checks

Keep each result within its evidence.

ProcessCore, QCore and AgriCore have separate project boundaries. A result in one project does not authorize a change in another.

  • Factory reuse across distinct jobs remains to be demonstrated.
  • Static checks establish a limited validation result; adoption and runtime behavior require separate evidence.
  • One no-effect control invocation does not authorize continuing activation or remediation.
  • The current public evidence does not establish production readiness, universal portability or hallucination elimination.
